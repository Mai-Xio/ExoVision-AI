# Physics-Informed Exoplanet Candidate Detection

A scientific report on the ExoVision AI pipeline.

> **Status of the results below.** Every number in §3 comes from **synthetic
> validation data** generated by `ml/data_access/synthetic_data_loader.py`. The
> section for real archive results (§3.2) is deliberately left empty. Synthetic
> and real results are never mixed in this document, and a synthetic number must
> never be quoted as a NASA result.

---

## 1. Research question

> Can physics-derived consistency features recover the discriminating power of
> the Kepler Robovetter's flag columns without using those columns — that is,
> without target leakage?

The question matters because the obvious approach works too well. Public Kepler
classifiers report 98–99% accuracy, and the usual explanation ("gradient boosting
is very good at tabular problems") is not the right one.

The NASA Exoplanet Archive defines a FALSE POSITIVE as an object that failed at
least one of the tests recorded in `koi_fpflag_nt`, `koi_fpflag_ss`,
`koi_fpflag_co` and `koi_fpflag_ec`, and it takes the non-CONFIRMED values of
`koi_disposition` from `koi_pdisposition`, the Robovetter's own verdict.
`koi_score` is the fraction of Monte Carlo Robovetter iterations returning
CANDIDATE.

```
koi_fpflag_* ──(rule)──▶ koi_pdisposition ──(copied)──▶ koi_disposition
                                ▲
                          koi_score
```

A model given those columns is not predicting anything. It is recovering a
deterministic function it was handed.

So the research question splits in two:

1. **How much apparent performance does that leakage buy?** (Measured, not assumed.)
2. **Can physics recover it legitimately?**

## 2. Methodology

### 2.1 Dataset

NASA Exoplanet Archive KOI table, retrieved via Table Access Protocol with a
provenance sidecar recording the exact ADQL, UTC timestamp and SHA-256 of every
download. The `cumulative` table is live and dispositions are revised over time,
so "I used the KOI cumulative table" is not a reproducible statement without
that hash.

Development and the results here use a physically-motivated synthetic generator.
Its false positives are produced by **simulating their physical cause** — a
diluted binary genuinely receives a biased density fit and a shallow depth —
rather than by drawing a label and perturbing features to match. This matters
methodologically: nothing in the generator writes the consistency features, so
when those features separate the populations, they are detecting the mechanism
rather than a correlation someone hard-coded.

### 2.2 Cleaning

Governing rule: **never drop rows on a quantity that correlates with the label.**

The common version of the mistake is "remove implausible planet radii above
30 R⊕ as data errors." Those rows are not errors. A 40 R⊕ object is an eclipsing
binary, it is labelled FALSE POSITIVE, and it is exactly the physics the model
should learn. Deleting it removes real signal, shifts the class balance, and
inflates every downstream metric — while looking like diligence.

Two operations with different licences:

| | When | Examples |
|---|---|---|
| **DROP** | Structurally unusable, reason carries no label information | missing `kepid`, duplicate `kepoi_name`, negative period |
| **FLAG** | Everything else; becomes a `qc_*` boolean the model may use | radius > 25 R⊕, depth > 10%, SNR below the 7.1σ pipeline threshold, assumed stellar parameters |

The cleaning report breaks every drop down by class. A test fails if any drop
reason is more than 90% one class — a drop that removes 90% false positives is
relabelling wearing a lab coat.

`NOT DISPOSITIONED` rows are held out, not dropped. They receive identical
treatment and are written separately as the inference target.

### 2.3 Grouped splitting

`StratifiedGroupKFold` on `kepid`, persisted once to `split.json` and read by
every downstream module.

A KOI name has an integer part designating the target star and a decimal part
identifying a unique transiting object on it, so multi-planet systems contribute
several rows sharing one `kepid`. Those rows share the host's temperature,
radius, mass, log g, magnitude, noise floor, neighbours and quarterly
systematics. A row-wise split lets a model memorise a host from its siblings, and
the optimism this produces is **invisible** — the test metric simply comes out
higher with no warning.

Persistence solves a second problem: if training splits with `random_state=42`
and explainability splits with `random_state=0`, the SHAP plots describe a model
evaluated on different data than the metrics table, and nothing errors.

Note the test set is 20% of *stars*, not of rows.

### 2.4 Feature sets

| Set | Contents | Status |
|---|---|---|
| A `baseline` | 22 directly measured and catalogued observational parameters | Valid |
| B `physics_informed` | A + consistency diagnostics + uncertainties + log transforms + QC flags (67 columns) | **Primary** |
| C `leaky_control` | A + `koi_fpflag_*` + `koi_score` (27 columns) | **INVALID — experiment only** |

Enforcement is structural, not conventional: `resolve()` raises if a quarantined
column enters a valid set, primary-model selection is restricted to valid sets,
and the prediction service refuses to load any artifact flagged
`scientifically_valid: false`.

### 2.5 Models

Logistic regression, random forest, XGBoost, RBF SVM and an MLP — each wrapped
in an sklearn `Pipeline` so that every fitted transformation (imputation,
scaling, encoding) learns only from the training fold.

No SMOTE. Real KOI imbalance is mild (~2:1); synthesising minority rows on a
grouped problem creates points belonging to no star, and applying it outside the
fold leaks. `class_weight="balanced"` instead.

Selection metric is **PR-AUC**, not accuracy. A majority-class predictor scores
~65% accuracy on this dataset while detecting nothing.

### 2.6 Physics features

Each compares two independent measurements of one physical quantity.

**Stellar density.** `koi_srho` is fitted from the light curve's period, depth
and duration (Seager & Mallén-Ornelas 2003); the archive states it is
independent of the listed stellar mass and radius, which come from photometry
and spectroscopy. Two disjoint routes to one number. They agree for a planet on
a near-circular orbit around the target star; they disagree under dilution,
eccentricity, or a mis-characterised host.

**Transit duration.** For a circular orbit `T = T₀·√(1−b²)`, so `T/T₀ ≤ 1`
always, where `T₀ = (P/π)(R★/a)` and `a/R★` follows from the stellar density.
This is a hard geometric bound rather than a learned threshold.

**Transit depth.** A geometric transit blocks exactly `(Rp/Rs)²`. Limb darkening
deepens a central transit (ratio typically 1.0–1.3); third light in the aperture
dilutes it (ratio below 1).

All supporting constants are verified against Solar System values in the test
suite: solar density 1.4101 g/cm³, R☉/R⊕ = 109.08, a(P=365.25 d, M=1 M☉) = 1.000
au, a/R★ = 214.9, central Earth transit duration 12.98 h, Earth equilibrium
temperature 254.6 K, Earth transit depth 84.0 ppm.

## 3. Key results

### 3.1 SYNTHETIC VALIDATION

> Generated data. Demonstrates that the code detects what it claims to detect.
> **Not scientific findings.**

Dataset: 4,000 generated KOIs → 3,811 after cleaning → 3,049 train / 762 test
rows across 2,260 / 562 host stars, 0 shared. Positive rate 0.534 train vs 0.534
test.

**Model comparison** (test set, single evaluation, best model per feature set):

| Feature set | Best model | Features | ROC-AUC | PR-AUC | F1 | Accuracy | Validity |
|---|---|---:|---:|---:|---:|---:|---|
| `baseline` | gradient_boosting | 22 | 0.9912 | 0.9922 | 0.9659 | 0.9633 | Valid |
| `physics_informed` | random_forest | 67 | 0.9956 | **0.9959** | 0.9708 | 0.9685 | Valid |
| `leaky_control` | random_forest | 27 | 1.0000 | 1.0000 | 1.0000 | 1.0000 | **INVALID** |

All 15 model × feature-set combinations trained successfully. Cross-validated
PR-AUC for the primary model: 0.9924 ± 0.0015 across five grouped folds.

**Consistency features separate by true physical cause.** Median
`|log₁₀(ρ_fit/ρ_cat)|`:

| True cause | Density ratio | Duration ratio |
|---|---:|---:|
| planet | **0.047** | 0.87 |
| eclipsing binary | 0.236 | 0.46 (grazing) |
| diluted / background EB | **0.496** | 1.17 |
| not transit-like | 0.434 | **2.32** (impossible) |

**Feature importance.** Permutation importance on the test set (drop in PR-AUC
when shuffled):

| Feature | Importance | Physics-derived |
|---|---:|---|
| `f_abs_log_rho_ratio` | **0.01046** | yes |
| `f_rho_ratio` | 0.00594 | yes |
| `f_log_rho_ratio` | 0.00579 | yes |
| `koi_ror` | 0.00432 | no |
| `f_depth_expected_ppm` | 0.00421 | yes |
| `f_ror_from_radii` | 0.00341 | yes |
| `f_duration_ratio` | 0.00250 | yes |

79% of the top 14 features are physics-derived. SHAP attributes **77.9%** of
total absolute contribution to `f_`/`qc_` features.

**Error analysis.** 11.4% error rate within the diluted/background EB class;
0.0% for plain eclipsing binaries and 0.0% for not-transit-like objects. Every
single test-set error is a diluted binary.

This is the correct failure mode. A diluted background binary is precisely the
case where the photometry looks most like a planet, and it is the case the
centroid test (`koi_fpflag_co`) exists to catch — the one piece of information
the physics features approximate rather than reproduce, because centroid offsets
are a pixel-level measurement not fully recoverable from the light curve alone.

**EarthLikeScore uncertainty propagation.**

| Case | Score | 5th–95th percentile |
|---|---:|---|
| Earth analogue, spectroscopic host (±3%) | 98.7 | 82.4 – 98.6 |
| Earth analogue, KIC-precision host (±30%) | 98.7 | **69.3 – 97.8** |
| Hot Jupiter | 9.6 | 8.6 – 9.9 |
| 1.6 R⊕ super-Earth in HZ | 75.3 | 54.9 – 89.5 |
| M-dwarf temperate, 1.1 R⊕ | 91.5 | 74.2 – 93.1 |

**Light curve analysis.** BLS recovered an injected 8.5000 d period as
**8.500449 d**, depth 563.8 ppm (from 900 ppm injected; the Savitzky-Golay
flattening absorbs part of the transit), empirical SNR 26.35, 10 transits in the
baseline.

**Transit classifier.** Trained with the gradient-boosting fallback because
PyTorch is not installed in this environment: test accuracy 0.983, F1 0.968,
ROC-AUC 0.9985. **The 1D CNN itself was not trained.**

**What to expect, stated in advance so it cannot be rationalised afterwards:**

- Absolute scores will be **lower**. The synthetic generating process is simple.
  Honest tabular KOI classification without Robovetter columns should land near
  0.93–0.96 PR-AUC.
- The physics-vs-baseline gap will be **smaller**. Real light curves have
  correlated noise, `koi_srho` fits carry genuine uncertainty, and eccentric
  planets populate the same density-mismatch tail as blends.
- The leaky control will still approach 1.0. That part is not a property of the
  data generator; it is a property of the label definition.
- If the consistency features show **no** separation at all, check units before
  concluding anything. `koi_duration` is in hours and `koi_period` in days, and
  that single mismatch produces a factor of 24.

## 4. Leakage experiment

The mandated experiment, and the clearest result in the project.

Three feature sets, identical models, identical folds. The leaky control reaches
**1.0000 on every metric**. Perfect ROC-AUC, perfect PR-AUC, perfect F1, perfect
accuracy — on a held-out test set with no shared host stars.

That is not a model. It is a lookup.

The reading is deliberately counterintuitive: **the tallest bars belong to the
model that must never be used.** A near-perfect score on a tabular KOI classifier
is evidence to investigate, not evidence of success.

Three consequences are enforced in code rather than in prose:

1. The leaky control is excluded from primary-model selection structurally — it
   cannot be selected however well it scores.
2. The prediction service refuses to load any artifact flagged
   `scientifically_valid: false`, so it cannot reach the API even by accident.
3. Every leaky figure carries a `LEAKY CONTROL — NOT VALID FOR SCIENTIFIC USE`
   watermark burned into the image, because figures get separated from their
   captions the moment someone drops one into a slide deck.

The honest comparison is `baseline` vs `physics_informed`: 0.9922 → 0.9959
PR-AUC, 0.9659 → 0.9708 F1. A real improvement, earned from measurements rather
than taken from the answer key.

## 5. Physics consistency features

### 5.1 Stellar density

The strongest single feature in the project by permutation importance.

Under dilution, the fitted depth is shallow and the inferred `a/R★` wrong, so
the fitted density departs from the catalogue value. Under eccentricity, the
transit speed at conjunction differs from the circular-orbit assumption, with the
same effect. Under a mis-characterised host — two stars treated as one — the
catalogue radius is wrong.

Those three cases cover most of the false-positive taxonomy, which is why one
feature does so much work.

### 5.2 Transit duration

The only feature here with a **hard** bound. `T/T₀ > 1` is not improbable under
the circular-orbit assumption; it is impossible. A model can use that as a
certainty rather than a tendency.

Synthetic medians: planets 0.87, eclipsing binaries 0.46, not-transit-like 2.32.
The not-transit-like population sits firmly in impossible territory, which is
what "not transit-like" means physically.

### 5.3 Transit depth

The weakest of the three, and worth saying so. Limb darkening and dilution push
the ratio in opposite directions, and a moderately limb-darkened diluted transit
can land near 1.0. It contributes, but it is not load-bearing.

### 5.4 What is not recoverable

The centroid test is a **pixel-level** measurement: it asks whether the
photocentre shifts during transit, which localises the eclipsing source on the
sky. No amount of light-curve algebra fully reproduces that, and the error
analysis shows exactly this gap — every test error is a diluted background
binary.

The honest conclusion is that the physics features recover *most* of the
Robovetter's discriminating power, not all of it, and the residual is
concentrated where you would predict from first principles.

## 6. Earth-like candidate analysis

### 6.1 Method

`EarthLikeScore`, 0–100, five smooth weighted components: radius (0.30),
incident flux (0.25), equilibrium temperature (0.15), habitable zone (0.20),
host star (0.10).

Every component is a smooth function. No hard cutoffs anywhere: a candidate at
1.26 R⊕ is not categorically different from one at 1.24, and the test suite
asserts the difference is under 0.05.

Habitable-zone boundaries use Kopparapu et al. (2013; 2014 erratum) quartic
coefficients. For the Sun these give 0.981–1.689 au conservative and 0.750–1.766
au optimistic. The optimistic pair matches published values exactly; published
conservative inner edges span 0.95–0.99 depending on revision and on whether the
runaway or moist greenhouse limit is used. The ~4% spread is documented rather
than papered over, and it is smaller than the stellar-parameter uncertainty on
most KOIs.

### 6.2 Uncertainty propagation

This is the part that distinguishes the score from a ranking formula.

Planet radius is `koi_ror × koi_srad`. The transit fits only the ratio; the
stellar radius is imported. For ~80% of KOIs that radius comes from broadband
photometry with a median fractional uncertainty near 30% — **wider than the
"Earth-sized" window itself**.

Monte Carlo sampling of the measurement uncertainties produces:

| Case | Score | Interval |
|---|---:|---|
| Earth analogue, ±3% stellar radius | 98.7 | 82.4 – 98.6 |
| Earth analogue, ±30% stellar radius | 98.7 | 69.3 – 97.8 |

Identical point estimates. Only the interval shows that one of these is a much
weaker claim. A score reported without its interval is reporting precision the
data does not contain.

Radius and flux are sampled in log space because their errors are multiplicative
— a normal draw would place non-trivial mass at negative radius at 30%
uncertainty. Equilibrium temperature is recomputed from each sampled flux
(`T ∝ S^¼`) so the two remain physically coupled.

### 6.3 Prioritisation

```
priority = P(planet-like) × (EarthLikeScore / 100) × data_quality
```

Multiplicative because the requirements are conjunctive. An eclipsing binary
whose incorrectly derived radius lands near 1 R⊕ scores well on Earth-likeness
and is still not a planet; the classifier term suppresses it. A candidate with
assumed stellar parameters and a missing insolation measurement gets suppressed
by the data-quality term even if both other factors are high.

This is a **prioritisation heuristic for ordering follow-up**, not a detection.

### 6.4 Limitations of the score

- The weights are author-chosen. They are configurable and defensible, not derived.
- The temperature and flux components are partly redundant by construction
  (`T_eq ∝ S^¼`), which is why temperature carries the lowest physical weight.
- Equilibrium temperature assumes albedo 0.3 and no atmosphere. Earth's 255 K
  equilibrium value sits 33 K below its mean surface temperature.
- The habitable zone says nothing about atmospheric retention, magnetic fields,
  tidal locking, or M-dwarf flare activity.

## 7. Limitations

**On the labels.** CANDIDATE means "not yet refuted", not "is a planet". Training
against catalogue dispositions imports the catalogue's own reliability as a
ceiling. The model can at best learn to reproduce vetting decisions, including
their errors.

**On the sample.** The `cumulative` table mixes deliveries vetted by different
Robovetter versions. Any completeness or occurrence-rate statement needs the
frozen `q1_q17_dr25_koi` table instead.

**On detection bias.** The period–radius plane has a sharp lower-right boundary
that is Kepler's sensitivity limit, not astrophysics. Anything a model learns
near that edge is about the instrument.

**On stellar parameters.** The dominant error source, and it propagates directly
into every Earth-like claim. Gaia parallaxes later revised many Kepler stellar
radii substantially, moving planets across the Earth-size boundary in both
directions.

**On the synthetic results.** They validate code, not astrophysics. The
generating process is simpler than reality in every respect that matters.

**On the deep learning module.** The 1D CNN was not trained in this environment.
Reported transit-classifier numbers come from a gradient-boosting fallback, which
cannot exploit translation invariance along the phase axis and is therefore not a
substitute.

**On what a classification is.** A model output is a triage score, not a
validation. Confirming an exoplanet requires centroid analysis, radial-velocity
follow-up, or statistical validation against astrophysical false-positive priors.

## 8. Conclusion

On synthetic data with a known generating process:

1. **The leakage is real and large.** A model given the Robovetter's flag columns
   reaches exactly 1.0000 on every metric. The 98–99% figures in the public
   literature are consistent with this mechanism rather than with model quality.

2. **Physics recovers most of it legitimately.** The physics-informed set
   improves on the baseline (PR-AUC 0.9922 → 0.9959) using only quantities the
   archive publishes anyway, and the stellar-density consistency check is the
   single most important feature by permutation importance.

3. **The residual is where theory predicts.** Every test error is a diluted
   background eclipsing binary — the case that needs pixel-level centroid
   information not recoverable from the light curve alone. The features recover
   most of the Robovetter's power, not all, and the gap is principled.

4. **Uncertainty is the binding constraint on Earth-like claims.** Two candidates
   with identical measurements score identically and mean very different things.
   Any Earth-like metric without propagated uncertainty is reporting precision
   that the stellar parameters do not support.

**These conclusions are provisional on synthetic data.** They establish that the
method works as designed; they do not establish what it finds in the Kepler
catalogue. The real-data run in §3.2 is the actual test, and the expectations
recorded there were written before it was run so they cannot be adjusted
afterwards.

Nothing in this project detects life, proves habitability, or confirms a planet.
It produces a prioritised list of candidates worth attention, with an honest
account of how much each entry can be trusted.
